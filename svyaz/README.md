# Связь

Прямой разговор Директора с исполнителем на одной машине. Без GitHub, без
браузера, без почтальона, без выхода в сеть.

Директор — Codex. Исполнитель — живое окно Claude в VS Code. Сидят за одним
столом: один компьютер, один пользователь, один диск. Связь просто открывает
между ними дверь.

## Куда она стучит — дословно

```
1. читает паспорт живого окна:  ~/.claude/sessions/<pid>.json
   там номер сессии и номер процесса; рядом .key — чтобы чужой не постучал
2. стучится сокетом типа AF_UNIX по адресу из паспорта
3. строка появляется в окне обычным сообщением
```

**`AF_UNIX` — это не сеть.** У такого сокета нет ни адреса в интернете, ни
порта, ни выхода наружу: он живёт только внутри машины, как дверь между
комнатами одной квартиры. Отключи интернет — Связь работать не перестанет.

Обратно так же: исполнитель отвечает в своём окне, Связь читает его журнал
**с метки, поставленной до отправки**, и отдаёт Директору. Старое за новое
не принимается.

## Чем пользоваться

```bash
python3 svyaz.py okna                    какие окна живы и какое выбрано
python3 svyaz.py komu-claude "текст"     положить исполнителю в окно
python3 svyaz.py ot-claude <метка>       забрать сказанное после метки
python3 svyaz.py krug "текст"            отдать и дождаться ответа
```

Директор — отдельной командой:

```bash
python3 direktor.py reshit   Codex смотрит доску и пишет задание, не отправляя
python3 direktor.py krug     даёт задание исполнителю через ворота Checklist
python3 direktor.py sudit    судит кандидата по файлам и ставит зачёт воротами
```

## Законы, которые здесь не обходятся

Связь ничего не решает сама. Все правила держит **AION Checklist**:

- один пункт в работе;
- исполнитель возвращает `PASS_CANDIDATE` · `FAIL` · `BLOCKED`, зачёт не ставит;
- зачёт пишут ворота и только по слову Директора при наличии улик;
- Директор не строит, исполнитель не судит.

## Из чего состоит

```
svyaz.py      дверь в обе стороны: положить в окно, забрать ответ
direktor.py   Директор: решить · дать · судить. Зовёт Codex местным
              app-server по stdio, ворота — обычной командой
letopis-svyazi.ndjson   что кому отдано и какой вердикт получен
```

Чужого кода нет. Опирается на три местных куска из `tools/muse`:
`v_sessiyu` (положить в окно), `iz_sessii` (прочесть журнал), `sessii`
(какие окна живы). Во всех трёх **ноль обращений в сеть** — проверено.

## Слабые места — названы честно

1. **Нужно живое окно.** Закрыл VS Code — задание не дойдёт. Это плата за
   то, что исполнитель не отдельная служба, а твоя сессия.
2. **Судья непостоянен.** Codex на одних и тех же уликах давал то `PASS`,
   то `FAIL` — мерено 19.09 дважды. Значит хорошую работу иногда завернёт.
3. **Ожидание ответа на глазок.** Считаем, что исполнитель договорил, когда
   текст перестал расти. Может обрезать длинный ответ или повиснуть.
4. **Нет повтора.** Не доставилось — никто не попробует снова.

## Почему не взяли готовое

Смотрели `cross-agent_mcp` (9216 строк) и `agent-relay`. Закрывают наши
слабые места, но устроены **обёрткой**: подменяют собой запуск обоих агентов,
и весь разговор идёт сквозь чужой код. Впятеро больше самой задачи, и именно
на самом узком месте. Отказались.

MCP оба конца умеют — `codex mcp add` есть, у исполнителя серверы подключены.
Но это дало бы только удобство вызова, а не надёжность. Строить будем, если
Связь порвётся именно там, где MCP чинит, — с доказательством в руках.
